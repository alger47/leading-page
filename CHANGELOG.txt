## Phase 16 — AI image generation for landing pages (2026-09-18)

Phase 16 master-prompt task: give fresh pages real raster art instead of placeholder-only media — generate images for `image`/`illustration` requirements, driven by the asset planner, at deterministic cost, without adding a GPU or object store to the free-tier stack. Two-part scope; this commit is **part 1 (generation)**. Part 2 (page generation from a product link, reusing product images) is designed but not built.

**Implemented:**
- **Engine Stage 6 `asset-renderer`** (`app/services/asset_renderer.py`): a deterministic code stage after asset-planner that maps each `image`/`illustration` requirement (`subject` + `orientation`, tone→style map `_TONE_STYLE`) to a stable positive prompt and renders one raster per requirement. Cap `AI_IMAGE_MAX=4`, `AI_IMAGE_SIZE=1024x1024`, `AI_IMAGE_MAX_BYTES=800_000`, `AI_IMAGE_TIMEOUT_S=120`. Icons are skipped (`kind` gate); the stage is **OFF by default** (`AI_IMAGE_PROVIDER=off`) and no-ops to an empty success when off, so stage listings never drift.
- **Image providers** (`app/providers/`): `ImageProvider` protocol (`ImageResult`), `HuggingFaceImageProvider` (free-tier Falcon Inference API over an injectable `transport`, bounded errors, backoff, `model_id` from env with routing-config fallback), `StubImageProvider` (deterministic 1×1 PNG, dev/tests only), `image_provider()` factory wired in `container.py` via the settings singletons; `force_image_for_tests()` swap.
- **Ephemeral asset flow (bytes in-memory, refs in DB):** engine `JobAssetStore` (in-memory, cap 100) ↔ worker `MemoryAssetStore` ↔ web `RasterMemoryStore`. Only the manifest goes into `JobResult.assets` — the saved schema/DB shape is unchanged and refs stay the existing logical `asset:<id>` form (SEM-011). New endpoints: engine `GET /internal/v1/assets/{job_id}/{ref}` (token-authed), worker `GET /api/jobs/:id/assets` (token-authed, `data_b64`), web `/assets/asset/{ref}` serves stored bytes **memory-first** then the deterministic placeholder SVG. ASP module `lib/assets.ts` SVG stays XML-escaped (Phase 14).
- **Opt-in, honest failure:** a job generates images only when the engine provider is enabled **and** the request is `generate_images: true` (new boolean on `POST /api/v1/jobs` via worker `POST_JOB_SCHEMA`, web `POST /api/v1/generate`, `POST /api/v1/projects/:id/pages`, and the `GenerationView` toggle). Any failing/over-cap/missing image becomes a benign warning issue `E-IMG-001` + `stage.draft=True` + placeholder; the job still COMPLETES (no fabricated success). Image attempts land in the job ledger with `model_class="image"`, `prompt_ref="image@<model_id>"`, per-image cost from routing `images.default.cost_per_image` (0.0 — HF free tier); job budget still guards overflow honestly (`E-AI-002`).
- **No new worker stable event** (§11.4 intact): stages stay as today; the manifest is a side channel the web pulls at finalize and relays into `RasterMemoryStore`. `WorkerClient.getAssets` is **optional** on the interface, so the e2e in-process fake worker stays source-compatible.
- **Docs:** `docs/adr/ADR-0012-image-generation.md` (decision + consequences), `docs/production-readiness.md` §2 env matrix + §9 generated-raster note + §10 residual #9 (ephemerality, HF variability).

Suite takes ~5 min (provider tests pace).

### Part 2 (shipped separately): page generation from a product link

**Implemented:**
- **Web product-source** (`apps/web/lib/product-source.ts`, `app/api/v1/product/extract/route.ts`): server-side bounded fetch of an allowlisted product URL (`PRODUCT_SOURCE_ALLOWLIST`, default `aliexpress.com`; http/https only, **SSRF-safe**). Document reads are capped at 2 MiB, images at 1 MiB each (skipped on oversize), max 4 images, **mime sniffed from bytes** (PNG/JPEG/WebP/GIF/AVIF) and cross-checked against the `content-type`. `E-PROD-001` (400) on any failure.
- **Layered extractor** (`lib/product-extract.ts`): Layer 1 recursive JSON walk of `runParams`-style globals, Layer 2 regex fallbacks (product-list JSON, Open-Graph tags); Title ≤120 chars, price normalization, bullets ≤8 × 300, images absolutized + de-duplicated + ≤8; `EMPTY_PRODUCT` degrades to the manual-brief path, never a 500.
- **Supplied-raster reuse end-to-end:** web `POST /api/v1/generate` accepts `productUrl`, re-derives `suppliedImages` (ref/mime/data_b64) server-side and forwards to the worker; worker `POST_JOB_SCHEMA` adds `suppliedImages` (maxItems 4, data_b64 ≤1 600 000 chars, `additionalProperties: false` preserved) and fingerprints over `count + sorted refs` so retries never rehash bytes; engine `POST /internal/v1/generate` accepts `supplied_images` (base64 validated/decoded, max 8) into the asset-renderer which consumes them **in order, one per requirement** (hero first) — `model_class="supplied"`, `prompt_ref="supplied@product"`, `provider="product"`, **zero cost** — then falls back to FLUX for the remaining requirements; oversized supplied → existing `E-IMG-001` + placeholder.
- **UI** (`components/generation-view.tsx`): product-link input + "Load" button, live thumbnails, pre-filled brief from title+bullets, `E-PROD-001` shown inline while the manual brief stays editable.

**Tests / verification:**
