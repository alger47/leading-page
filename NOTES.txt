## Phase 6 Completion (2026-09-09):

**Worker & job orchestration (apps/worker, TypeScript + fastify + BullMQ):**
- **Port layer (ADR-0004):** `queue/ports.ts` (EnqueueDriver/JobLike/WorkerHandle), `queue/bullmq.ts` (production, real ioredis), `queue/memory.ts` (test driver). The PROCESSOR has no BullMQ imports — identical under both drivers.
- **ioredis-mock rejection:** BullMQ Lua (`addStandardJob`) needs `cmsgpack`, which ioredis-mock's fengari sandbox lacks → decided to de-couple tests from any Redis rather than fight the mock.
- **API surface (§11):** POST /api/jobs → 202/200 (replay via Idempotency-Key or derived fingerprint `derived:sha256(brief+locale+tone+budget)`), 422 E-JOB-002 same-key-diff-payload; GET /:id, /:id/events, /:id/spans; DELETE /:id (E-JOB-003, 409 if terminal); GET /healthz.
- **States:** QUEUED→RUNNING→(VALIDATING/RENDERING reserved)→COMPLETED/FAILED/CANCELLED. Events: job.queued/started/retried/completed/failed/cancelled + stage.brief_analyzed/page_planned/content_generated/schema_built/validated.
- **Job id = engine job id:** `gen_<sha256(key)[0:24]>` — the idempotency key fingerprints into a stable engine job id, so `/internal/v1/pages/{job_id}` + `/ledger` are addressable (engine echoes it).
- **Failure taxonomy learned while bring-up:**
  - Transient (5xx, timeout, network) → E-JOB-001, retried with exponential backoff (default 3 attempts); exhaustion finalized by the worker failed-handler.
  - 422 with detail.code (E-AI-001), job.status FAILED (E-AI-005), budget (E-AI-002) → terminal, attempts stay at 1. **Bug caught:** 5xx-without-detail.code used to fall through to E-JOB-004; now 5xx always → E-JOB-001 (only <500 no-code → E-JOB-004).
  - Malformed envelope (non-JSON / wrong shape) → E-JOB-004, no retry.
  - Idempotency conflict MUST return 422 — first cut left HTTP 500 (error had no statusCode).
- **Crash recovery:** RUNNING records re-run in place with job.retried {code: E-JOB-005}.
- **Engine token pitfall (E2E):** engine rejects x-internal-token unless it equals AI_INTERNAL_TOKEN (default `dev-internal-token`). Harness used `test-token` → real-engine job 401'd and appeared to hang forever (401 → bucket business → FAILED, tests poll for COMPLETED). Aligned e2e env AI_INTERNAL_TOKEN=test-token. Fake engine ignores token, so unit tests never caught it.
- **Real engine stage-tracking:** /internal/v1/generate `stages` = the 5 sub-generation steps (brief-analyzer, page-planner, layout-planner, content-generator, asset-planner) — schema-builder/page-validator are internal, NOT reported. Real-engine e2e therefore asserts a well-formed event frame + the reported stages, not a fixed 7-stage list (the fake engine still returns the 7-stage payload for deterministic unit tests).

**Prisma on pnpm (v12) gotchas:**
- Install fails with `ERR_PNPM_IGNORED_BUILDS` until `allowBuilds` includes `prisma`, `@prisma/client`, `@prisma/engines` (pnpm then rewrites the workspace yaml with a literal `set this to true or false` line → prune the duplicate before re-running).
- Prisma 6.19.3 works offline (engines ship via optional deps); Node 26 ok.
- `prisma migrate dev` is interactive-ish; add a `migrate status` fallback to confirm applied migrations when the update banner eats the output.
- **Prisma `@unique` emits `CREATE UNIQUE INDEX`**, NOT a `pg_constraint` row — constraint-presence tests must introspect `pg_indexes` (check `indexdef LIKE '%UNIQUE%'`), not `pg_constraint`.
- Prisma `$executeRawUnsafe` refuses multi-statement strings ("cannot insert multiple commands into a prepared statement") — split DROP SCHEMA / CREATE SCHEMA into two calls.

**Schema/JSONB pitfalls:**
- JSONB round-trips reorder object keys (alphabetical-ish after another write) — version-immutability tests must compare deep equality (toEqual), never raw JSON strings.
- Prisma Json (`JsonValue`/`InputJsonValue`) typing is strict: `Record<string, unknown>` is NOT `InputJsonValue`; passing reusable content is cleanest as `content: unknown` in the repo input, validated (L1) then cast `as Prisma.InputJsonValue` at insert. Json `null` must be `Prisma.JsonNull`, not JS `null`.
- Json field arrays (eventsJson) read back as `JsonArray`, not `JobEvent[]` — cast through `unknown`.

**Optimistic concurrency, real semantics:** read `latest` in a txn, then insert next version; a concurrent writer hitting the `unique(page_id, version_number)` race surfaces as Prisma `P2002` — map BOTH the explicit baseVersion mismatch and P2002 to the same `OptimisticConcurrencyError`. Promise.allSettled verified: exactly one of two concurrent `saveVersion(base=2)` wins, sequence stays [1,2,3].

**Tenant isolation at the SQL level (§10.5):** every read is `findFirst({ where: { id, project: { id, userId: owner.userId, archivedAt: null } } })` — cross-tenant touches throw `NotFoundError` (no existence disclosure). Archived projects drop out of ALL child access. Isolation matrix across all 6 repositories green.

**Seed idempotency:** naive re-run broke on (a) page `saveVersion(base 0)` when v1 existed and (b) duplicate job idempotency keys → guard every insert behind an existence check (listVersions empty / get catches / published getForPage null).

**Test runtime world:** DB tests drop + replay the whole schema each run (`globalSetup` → `prisma migrate deploy` via `pnpm exec prisma migrate deploy` with `DATABASE_URL`); files MUST run serially (`fileParallelism: false`) or another file's truncate deletes this file's fixtures mid-test.

### Phase 7 Notes (Web Application):

**Auth (zero-dep):** scrypt (node:crypto) `scrypt$N$r$p$saltB64$hashB64` + constant-time compare; named session token in httpOnly `sid` cookie (30d) with a DB Session row; CSRF double-submit = readable `csrf` cookie + `x-csrf-token` header on every mutation (only the API enforces it; UI form posts auto-carry it). `requireAuth` resolves `Owner{userId}` for the §10.5 tenant-scoped repos.

**Generation UX / orchestration:** one POST /api/v1/generate -> `GenerationService.start()` derives `doc:userId:pageId:retryNonce` (nonce = count of prior terminal FAILED+CANCELLED), creates/dedupes the DB job with the SAME `gen_sha256(key)[0:24]` id the worker computes, then enqueues via §11 POST /api/jobs. `liveSync()` (runs on GET /generation-jobs/:id) appends unseen worker events, mirrors in-flight status, and on terminal calls one guarded `finalize()`: persist L1-valid PageVersion + COMPLETED, or record the worker's REAL error.code. `runExclusive` per job serializes poll-vs-finalize.

**State machine patch:** QUEUED now allows VALIDATING and COMPLETED (fast real worker completes before the first web poll). Terminal lock + backwards transitions unchanged; QUEUED -> RENDERING still illegal. WITHOUT this, the swallowed finalize left the job QUEUED AND re-saved a duplicate PageVersion on every poll (fixed + regression test updated).

**versionNumber semantics:** saveVersion = current + 1, so the FIRST draft is version 1 (assert `1`, never `0`). baseVersion = listVersions().length is correct.

**Idempotency:** same body re-POST -> 200 + same jobId; new attempt after FAILED/CANCELLED -> fresh nonce -> fresh jobId. Worker-loss mid-flight (view 404/empty) -> honest E-JOB-004 in the DB. Enqueue failure -> DB FAILED with the real code. jsonError: 4xx keep their code, 5xx collapse to E-INTERNAL-001 (never leaks).

**Next/styled-jsx (App Router):** `<style jsx>` is client-only; dashboard/project-detail views are `'use client'`; the (dashboard) layout + page-detail server components moved styles into one globals.css (inline styles everywhere, zero runtime CSS imports). Build output: all routes server-rendered (ƒ) except static /_not-found + /api/v1/healthz.

**Package boundary (build must pass):** apps/web imports workspaces via node_modules dist ONLY (tsconfig has just `@/*`). A stale .next cache after a tsconfig change mimics a "cannot resolve" bug — rm -rf .next first. Vitest aliases workspace packages to src (vite maps .js->.ts), so tests run against source.
